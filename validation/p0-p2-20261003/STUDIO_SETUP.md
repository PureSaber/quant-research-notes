# Studio首次配置向导验收

2026-10-04完成P1.1的网页首次配置闭环。用户可集中选择已有工作区、各应用Python、数据或研究配置，以及已有账户来源文件；校验、预览、明确保存后，重启可恢复相同选择。平台仍为十一个模板、十个业务预检入口。

实现已由[Studio#17](https://github.com/PureSaber/quant-studio/pull/17)合并。核验源码提交为`d3b176da7e08c8fa4845d211161a9f2befeecb57`，合并提交为`b6f8a9f82313650606e26636ca55dd121920625c`。本页不将该软件增量解释为真实业务认证、策略有效性或新增自然前向。

## 功能与正确性边界

原入口依赖分散的启动环境变量，网页无法集中保存选择。新增`quant-studio.settings/v1`及首次配置页面，复用现有模板、运行环境和账户契约。

- 保存位置由服务启动时确定，默认位于研究记录目录，也可用`serve --settings`明确指定。网页不能提交任意保存目标。
- 保存内容绑定已校验的预览令牌和旧文件字节；再次校验来源及文件版本，拒绝未知既有文件、路径链接、硬链接、文件变化和失效预览。
- 请求使用独立配置快照，子进程继承该快照；保存新设置不改变正在运行的旧请求，也不修改进程环境变量。
- 空字段保留启动配置语义。显式选择工作区而未填写输入时，要求补充输入，不猜默认数据目录。
- 配置检查与原生数据预检分别展示。填写路径不代表数据质量、研究可行性或投资适用性已经通过。
- 账户来源仅连接已有JSON；既有登记、账户、原始输入和冻结环境保持只读。

Windows远端集成曾失败：系统Python在环境根目录，console scripts在Scripts目录，而原解析器假定命令与Python同目录。本地虚拟环境恰好满足旧假设，因此没有暴露问题。修复从明确选中的解释器查询`sysconfig.get_path('scripts')`；探测失败或所选环境没有命令时拒绝运行，不借用全局PATH。

- 测试包括HTTP同源与CSRF、未知/重复字段、保存版本、失效预览、输入消失、重启恢复、硬链接拒绝、并发请求隔离，以及系统Python/虚拟环境脚本目录解析。
- PR最终20项检查全部成功，覆盖Windows/Linux单元测试、七类上游及择时集成。旧Windows港股失败日志保留，不用旧提交的成功结果替代最终提交检查。
- 合并提交的tests与Upstream integration工作流也均已成功，分别为37171394060和37171394052。
- GUI完成空配置保存与合成运行；不存在的Python、缺少上游命令及缺失输入明确拒绝，保留填写内容和旧配置。
- 保存真实港股配置后停止并重启服务，工作区、独立Python和快照恢复。原生预检覆盖5个标的、1535行价格，再以500000元本金和5日调仓的相同参数运行。

真实港股仍使用既有回顾性价格样本，公司行动不完整，`investable=false`。所有重放均不增加独立前向日期。真实GUI与主chat独立真实重放在首个功能提交阶段执行；后续脚本目录修复由完整单测、原生集成和Windows真实系统Python环境的CI再次验证，补充宽屏图在最终源码下采集。
