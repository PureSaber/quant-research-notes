# 候选与研究家族失败展示

2026-10-03，[Report Hub#23](https://github.com/PureSaber/quant-report-hub/pull/23)补齐P1.2的候选及家族失败展示。[脱敏验收回执](evidence/failure-visibility.json)记录原生收集器结果、重试与主实验失败场景、完整测试及实际浏览器截图哈希。本次使用合成输入，不新增独立市场研究证据。

## 根因与修正

原研究报告的诊断在主实验缺失或固定样例分支提前返回，导致末尾的候选失败提示被跳过；重试前的失败虽保存在登记库中，页面只显示当前候选及审计事件总数。家族证据页则把完整尝试清单和缺失原因放在折叠的原始JSON中，不便直接判断证据是否齐全。

现在候选未完成的诊断先于提前返回分支建立，页面先展示当前候选完整性，再单独列出失败、中断和未结束尝试。重试成功不删除旧失败；当前候选全部完成仍只表示当前产物齐全，不声明完整家族统计通过。原先成功候选的描述性指标继续保留，不能用其替代族级结论。

家族证据页直接读取既有收集器的计划清单、状态、缺失及核验错误，并展示所有成员。家族审计不可用时明确显示统计结论不可用；如果同一快照的统计方法又声称可用，拒绝生成矛盾报告。没有删除候选、改变登记、重算统计量或降低既有统计门槛。

## 验证

- 本机完整151项测试通过，5项既有条件跳过；总覆盖率88.69%，归因模块纯分支93.39%，Ruff与格式检查通过。Python3.10/3.11/3.12及CodeQL全部通过后合并。
- 新增回归覆盖主实验与压力候选失败、固定样例提前返回、重试成功保留旧失败，以及原生家族收集器的失败/缺失成员和矛盾证据拒绝。
- 原生`collect_family`与`evaluate_family`生成的合成场景包含3个尝试或占位项：成功候选、失败候选和未登记研究。审计不可用、统计方法数为0，网页直接显示三项及原因。
- 成功重试场景当前4个候选全部完成，仍显示1次旧失败，并要求单独核验完整家族证据。
- 主实验失败场景同时显示候选族统计不可用与主实验不可用，失败收益保持缺失。错误中的HTML特殊字符按文字显示，未成为可执行页面内容。
- 三份报告均在实际浏览器中查看，截图只保存在本机；临时服务与标签已关闭。冻结r4/r5研究输入、账户和自动化未更改。
